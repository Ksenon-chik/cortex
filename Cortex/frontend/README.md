# Cortex Frontend

Frontend-часть Cortex на Next.js 14. Приложение отвечает за публичный лендинг, ленту событий, карточку события с `Generate Forecast`, профиль пользователя и админ-панель.

## Что есть сейчас

- Лендинг и базовая навигация
- Лента событий с поиском, фильтрами и переключением режимов отображения
- Страница события с историей прогнозов и SSE-генерацией нового прогноза
- Leaderboard моделей по `brier_score`
- Регистрация, логин и профиль пользователя
- Подключение пользовательских API-ключей по провайдерам
- Админка с вкладками пользователей, моделей, событий и базы данных
- В админке у событий есть фильтр по дедлайнам и календарный режим отображения

## Технологии

- Next.js 14 (App Router)
- React 18
- TypeScript
- Tailwind CSS
- TanStack Query
- TanStack Table
- React Hook Form
- Zod
- Recharts

## Структура

- `app/page.tsx` — лендинг
- `app/events/page.tsx` — список событий
- `app/events/[id]/page.tsx` — карточка события и генерация прогнозов
- `app/leaderboard/page.tsx` — таблица лидеров
- `app/login/page.tsx`, `app/register/page.tsx` — auth flow
- `app/profile/page.tsx` — профиль и API-ключи
- `app/admin/page.tsx` — административный интерфейс
- `app/api/[[...path]]/route.ts` — прокси на backend

## Локальная разработка

```bash
pnpm install
pnpm dev
```

По умолчанию приложение поднимается на `http://localhost:3000`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BACKEND_URL` | URL backend-сервиса, на который проксируются запросы из `app/api/[[...path]]/route.ts` |

Пример:

```env
BACKEND_URL=http://localhost:8000
```

## Важные замечания

- Frontend работает через same-origin proxy и не требует публичного URL API в браузерных переменных
- Меню выбора моделей на странице события ожидает, что backend вернёт модели с корректным `provider`, иначе фильтрация по провайдеру работать не будет
- Часть административной логики опирается на серверные данные о моделях, пользователях и импортированных событиях, поэтому для полноценной локальной проверки нужен backend с базой данных
