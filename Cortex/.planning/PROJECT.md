# Cortex

## Описание проекта

Cortex — рабочая веб-платформа для анализа событий Polymarket и генерации AI-прогнозов с последующей проверкой точности. Проект уже включает пользовательские аккаунты, BYOK-подключение API-ключей, административный импорт событий, журнал прогнозов и leaderboard по Brier Score.

## Ключевая ценность

Показывать не только ответ модели, но и её реальную историческую точность на разрешившихся событиях.

## Текущее состояние продукта

### Реализовано

- [x] Лента событий с поиском, фильтрами и карточкой события
- [x] Генерация прогноза по событию с потоковым выводом статуса
- [x] Журнал прогнозов по событию
- [x] Таблица лидеров моделей по `brier_score`
- [x] Регистрация, логин, refresh, профиль
- [x] Пользовательское подключение API-ключей провайдеров
- [x] Админ-панель пользователей и моделей
- [x] Ручной поиск и импорт событий из Polymarket
- [x] Фоновая проверка резолюции событий и пересчёт точности
- [x] Freemium-лимит на прогнозы для бесплатного тарифа

### Реализовано частично / требует доработки

- [~] Вайтлист и админ-апрув присутствуют в модели и интерфейсе, но не образуют жёсткий контур допуска ко всем сценариям
- [~] Premium-план влияет на квоты, но ещё не выделяет отдельный premium-only каталог моделей
- [~] Документация и research-файлы долго отставали от кода — синхронизация выполняется этим обновлением

### Не реализовано

- [ ] Шифрование пользовательских API-ключей в базе
- [ ] Полноценный production-hardening вокруг мониторинга, аудита и секретов
- [ ] Автоматический каталог/синк всех рынков Polymarket без участия администратора

## Подтверждённые требования

- Пользователь должен видеть список событий и уметь открывать отдельное событие
- Пользователь должен уметь запустить прогноз по событию и увидеть результат с объяснением
- Система должна хранить историю прогнозов и давать сравнить модели по фактической точности
- Администратор должен уметь управлять доступными моделями и импортируемыми событиями
- Платформа должна поддерживать BYOK-сценарий для нескольких провайдеров

## Ограничения

- Текущий стек: FastAPI + Next.js + PostgreSQL, без планов на смену в ближайшем цикле
- События из Polymarket сейчас попадают в систему через ручной импорт в админке
- Планировщик запущен в приложении и безопаснее всего работает в одном backend-инстансе
- Пользовательские API-ключи пока хранятся без шифрования, что ограничивает production-ready статус

## Ключевые решения

| Решение | Статус | Почему это важно |
|---|---|---|
| Ставка на BYOK-подход для LLM-провайдеров | Принято | Уменьшает операционные расходы проекта и даёт пользователю контроль над поставщиком |
| Ручной импорт событий через админку вместо автосинхронизации всего рынка | Принято | Позволяет контролировать качество и размер локальной базы |
| Расчёт Brier Score после резолюции как главная метрика качества | Принято | Это центр продукта и отличает платформу от обычного чат-интерфейса |
| SSE-поток для генерации прогноза | Принято | Пользователь видит прогресс, а не «замёрзший» экран ожидания |
| Admin-managed каталог моделей | Принято | Можно включать/выключать модели и провайдеров без деплоя |

## Вне области текущего цикла

- Мобильное приложение

- Автоматическая агрегация нескольких моделей в единый «суперпрогноз»
- Торговые/ордерные сценарии Polymarket

Папка `.planning/phases/` хранит исторические слепки предыдущего планирования. Их полезно читать как журнал эволюции проекта, но за текущее состояние нужно считать именно `PROJECT.md`, `STATE.md`, `ROADMAP.md` и research-файлы.
