# Requirements Snapshot

Этот файл — короткий контрольный список требований по текущему коду, а не по исходной идее проекта.

## Core user flow

- [x] Пользователь видит список событий
- [x] Пользователь может открыть отдельное событие
- [x] Пользователь видит историю прогнозов по событию
- [x] Пользователь может запустить новый прогноз по событию
- [x] Пользователь видит leaderboard по точности моделей

## Auth and account

- [x] Пользователь может зарегистрироваться
- [x] Пользователь может войти и восстановить сессию
- [x] Пользователь видит свой профиль
- [x] Пользователь может подключать и удалять свои API-ключи
- [~] Пользовательский доступ частично контролируется whitelist/admin approve логикой

## Admin

- [x] Администратор может просматривать пользователей
- [x] Администратор может апрувить пользователей и менять им план
- [x] Администратор может повышать пользователя до администратора
- [x] Администратор может управлять моделями
- [x] Администратор может искать события Polymarket
- [x] Администратор может импортировать события в локальную БД
- [x] Администратор может ресинхронизировать или удалить событие
- [x] Администратор имеет доступ к служебной информации о размере БД

## Forecast and scoring

- [x] Система сохраняет прогнозы в БД
- [x] Система рассчитывает `brier_score` после резолюции события
- [x] Система показывает рейтинг моделей по качеству
- [x] Система поддерживает несколько AI-провайдеров
- [~] Премиум-поведение пока выражено главным образом через quota bypass

## Operational constraints

- [x] Проект использует PostgreSQL и Alembic
- [x] Проект использует встроенный scheduler для resolution jobs
- [ ] Проект ещё не шифрует пользовательские API-ключи
- [ ] Проект ещё не имеет полного production-hardening для секретов и observability
